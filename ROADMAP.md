## Текущее состояние

### Архитектура
- **`telegram_bot/`** — aiogram-бот для Telegram. Работает через бизнес-аккаунт (`business_message`), плюс роутеры для специалистов и группы. Polling через `AiohttpSession` (опционально с прокси).
- **`bitrix_qa_agent/`** — LangGraph-граф для QA. Пайплайн: проверка смены интента → проверка негатива → нужен ли ответ → положительный отклик → нужна ли БЗ → RAG (поиск статей, отбор, формирование контекста, ответ).
- **`loader/`** — отдельный сервис для загрузки базы знаний (статьи + примеры диалогов) в Postgres с векторными эмбеддингами.
- **`media_recognizer/`** — распознавание текста из медиа-сообщений (фото, голос и т.п.).
- **`alembic/`** + **`alembic_articles/`** — два набора миграций: основной для бота и отдельный для базы статей.
- **PostgreSQL + pgvector** — хранение чатов, сессий, сообщений и векторных эмбеддингов статей/диалогов.
- **Внешние LLM** — через OpenRouter (`pro_model`, `lite_model`), эмбеддер через свой клиент.
- **Деплой** — Docker-образ собирается локально через `buildx`, пушится в Docker Hub, на сервере `compose pull && up -d`.

### Что работает
- Приём сообщений клиентов через бизнес-аккаунт + команды специалиста.
- Распознавание медиа (через `media_recognizer`).
- Двухрежимная сессия (AI / специалист) с переключением через `takeover` и при негативе.
- RAG-ответы на основе базы знаний (статьи) и базы исторических диалогов.
- Автоответ + ответ на положительный отклик + перевод на специалиста при негативе.
- Прокси для запросов к Telegram и эмбеддеру (для обхода блокировок).

## Доработки и фиксы

### P0 — критично, блокирует пользователей
- [x] **Ретрай на `ValidationError` в LangGraph-нодах** (`bitrix_qa_agent/nodes.py:110-112` и `nodes.py:226-228`).
  Сейчас в `chain.with_retry(...)` указан только `OutputParserException`, а при обрезанном JSON от LLM (`with_structured_output`) летит `pydantic_core.ValidationError`. Граф падает с первой попытки, клиент не получает ответ от бота вообще.
  **Симптом в логах:** `ERROR:aiogram.event:Cause exception while process update ... ValidationError: Invalid JSON: EOF while parsing`.
  **Сделано:** добавлен `pydantic.ValidationError` в `retry_if_exception_type` для `need_reply_check` и `get_relevant_articles_ids` — 3 попытки. Backoff с джиттером настроен через `exponential_jitter_params={"initial": 2, "max": 10}` (паузы ~2–3с / ~4–5с) — даёт прокси/OpenRouter время прийти в себя при rate-limit и обрывах стрима.

### P1 — высокий приоритет
- [ ] **Сохранять сообщение клиента в БД сразу при входе** в `telegram_bot/message_handlers/client.py:handle_client_message`.
  Сейчас INSERT в `messages` выполняется только **после** успешного ответа QA-агента. Если граф упал — сообщение **теряется** в БД (в Telegram-чате остаётся, но возникает рассинхрон), и следующее сообщение в сессии обрабатывается без контекста предыдущего.
  Понадобится аккуратно перестроить формирование `chat_history` в графе (исключать последнее сообщение, чтобы `check_new_intent` корректно отрабатывал).

### P2 — средний приоритет
- [ ] **Стабильность polling через прокси.** В логах регулярно: `TelegramRetryAfter`, `Bad Gateway`, `ServerDisconnectedError`, `Request timeout`. Задать таймауты в `AiohttpSession` и обернуть `dp.start_polling` в supervisor-цикл с реконнектом, чтобы при затяжных разрывах бот гарантированно восстанавливался.
- [ ] **Таймзона контейнера на `Europe/Moscow`.** Сейчас контейнер в UTC, логи в UTC, а сервер и Telegram-UI в MSK — постоянная путаница при разборе инцидентов. Добавить `TZ: Europe/Moscow` в `docker-compose.yml` сервису бота.

### P3 — мелочи и тех.долг
- [ ] **Подавить безвредный pydantic `UserWarning`** (`PydanticSerializationUnexpectedValue` про `field_name='parsed'`) от связки `langchain-openai` + `with_structured_output` — засоряет логи, никак не влияет на работу.
- [ ] **`LangChainPendingDeprecationWarning` про `allowed_objects` в `langgraph.checkpoint.serde.jsonplus`** — сейчас warning, но в будущей версии станет breaking change. Передать явное значение `allowed_objects='messages'` или `'core'` там, где используется `JsonPlusSerializer`.
- [ ] **Рефакторинг графа** (TODO из `bitrix_qa_agent/nodes.py:1, 174`):
  - Выделить RAG-часть в сабграф.
  - Выделить ветку после `knowledge_required_check` в сабграф.
  - Переименовать `NEED_KNOWLEDGE_DATABASE_PROMPT` (упоминание в `nodes.py:154`).
- [ ] **Артефакты разработки.** В корне модулей лежат `loader/some.py` и `telegram_bot/some.py` (untracked в git) — проверить, нужны ли, иначе удалить.
- [ ] **Логирование текста сообщений.** Сейчас текст входящего сообщения нигде в логах не светится (только в SQL INSERT, и то лишь после успешного сохранения). При разборе инцидентов это мешает. Возможные варианты: `DEBUG`-лог с обрезкой / маскировкой PII, либо отдельный аудит-логгер.
